文件内容搜索工具 软件需求说明

2026-10-11 　ZhaoZhao / zhaozhao.exe 　Windows 单机桌面工具

P0首个完整版本必须实现P1应当实现P2后续按需

1. 概述

本软件是一个 Windows 单机桌面工具，对本机硬盘、移动硬盘和网络映射盘上 1 万至 10 万个文件建立全文索引，支持按文件内容快速查找文字。

背景。 需要查找的文字分散在大量文件中，文件分布在多个磁盘和目录下，格式包括文本、代码、Office、WPS、PDF 和扫描件。系统自带搜索和 Everything 等工具主要按文件名查找，按内容查找要么很慢，要么不支持老格式和扫描件。

目标。

  • 输入关键词后 1 秒内看到结果，并能直接看到命中位置的上下文。
  • 覆盖日常工作中的主要文件格式，包括大量存在的 .doc/.xls/.wps 等老格式，以及需要 OCR 的扫描件和图片。
  • 支持关键词、短语、布尔组合、正则和模糊匹配。
  • 移动硬盘拔掉后仍可搜索其中内容，并提示需接入哪块盘才能打开文件。
  • 建索引在后台进行，不影响正常使用电脑。

使用形态。 单用户、单机运行，所有数据只存在本机，不联网，不提供多人共享。

名称。 找找，英文名 ZhaoZhao，程序文件名 zhaozhao.exe。取意「找东西」的口语说法，两个字、同字重复，好念好记，也和全局快捷键里的 F（Find）对应。

术语。 本文中「索引根」指用户添加进来、需要建索引的目录；「卷」指一个磁盘分区或一块移动硬盘；「提取」指从文件中取出纯文本的过程。

3. 索引范围与目录管理

用户自己指定要建索引的目录，软件不默认扫描整台电脑；隐藏文件默认纳入，系统目录和开发依赖目录默认排除。

编号 需求 优先级
F-IDX-01 用户可添加、移除、暂停多个索引根，索引根可以是目录或整个盘符 P0
F-IDX-02 每个索引根可单独设置要包含的文件类型和排除规则，未设置时使用全局规则 P1
F-IDX-03 隐藏文件和隐藏目录默认纳入索引 P0
F-IDX-04 内置默认排除清单（见下），用户可增删，可一键恢复默认 P0
F-IDX-05 排除规则支持：任意层级的目录名、路径前缀、通配符（glob）、扩展名 P0
F-IDX-06 按文件大小设上限，超出的文件只索引文件名，不提取内容；文本类默认 100 MB，其他类型默认 200 MB，可调整 P0
F-IDX-07 默认不跟随符号链接和目录联接（junction），避免重复索引和死循环；可按索引根开启 P0
F-IDX-08 OneDrive 等云盘中「仅在线可用」的占位文件默认跳过，避免触发下载 P1
F-IDX-09 无权限访问的目录和文件记录到日志并跳过，不弹窗 P0
F-IDX-10 未知扩展名的文件抽样判断是否为文本，是则按文本索引（可关闭），便于覆盖各种代码和配置文件 P1
F-IDX-11 所有被扫描到的文件，无论内容能否提取，文件名和路径都进入索引，可按文件名搜索 P0

默认排除清单：

  • 系统目录：C:\Windows、C:\Program Files、C:\Program Files (x86)、C:\ProgramData、各盘的 $Recycle.Bin 和 System Volume Information。
  • 系统文件：pagefile.sys、hiberfil.sys、swapfile.sys。
  • 临时目录：%LOCALAPPDATA%\Temp。
  • 开发依赖和版本库目录（任意层级）：node_modules、.git、.svn、.hg、__pycache__、.venv。
  • 软件自身的数据目录。

4. 文件格式支持

文本、Office、WPS、PDF、扫描件、压缩包和邮件在第一个完整版本中全部支持；老格式数量多，转换组件是必备项而不是可选插件。

类别 扩展名 提取方式 定位信息 优先级
纯文本、代码、配置 txt、md、log、csv、json、xml、yaml、ini、各类源代码 直接读取，自动识别编码 行号 P0
网页 html、htm 去除标签后取正文 行号 P1
Office 新格式 docx、xlsx、pptx 及 docm、xlsm、pptm、dotx、xltx 直接解析内部 XML Word：段落；Excel：工作表 + 单元格；PPT：幻灯片号 P0
Office 老格式 doc、xls、ppt、rtf 格式转换组件 同上（尽力而为） P0
WPS 格式 wps、et、dps 格式转换组件 同上（尽力而为） P0
PDF（有文字层） pdf 直接提取文字 页码 P0
PDF（扫描版） pdf 逐页判断，无文字层的页送 OCR 页码 P0
图片 jpg、jpeg、png、bmp、tif、tiff（含多页）、webp OCR 多页 tiff 记页码 P0
OpenDocument odt、ods、odp 直接解析内部 XML 同 Office P2

提取要求：

  • 文本编码自动识别 UTF-8（含 BOM）、UTF-16、GBK、GB18030、Big5，无法确定时按 GB18030 处理。
  • Word 提取范围包含正文、表格、页眉页脚、脚注、批注和文本框；Excel 包含所有工作表的单元格值和批注，公式取计算结果；PPT 包含幻灯片正文和备注。
  • PDF 按页判断是否有文字层，同一个文件中有文字层的页和扫描页可以混合处理。
  • 受密码保护的文件跳过，状态标记为「已加密」，文件名仍可搜索。
  • 每个文件的提取设超时（文本和文档默认 60 秒，OCR 按页另计）；超时或解析失败标记为「失败」并记录原因，不阻塞队列。

OCR 要求：

  • 离线识别简体中文和英文，不依赖网络和 Python 环境。
  • 可按索引根开关图片 OCR；默认跳过短边小于 200 像素的图片，避免为图标和缩略图浪费时间。
  • 识别结果按文件内容哈希缓存，文件移动、改名或复制后不重复识别。
  • Office 文档中内嵌图片的 OCR、繁体中文识别为 P2。

压缩包与邮件：

压缩包和邮件都是「容器」：软件把里面的每个文件、每封邮件和每个附件当作独立的搜索结果，按上面的规则提取内容。

类别 扩展名 处理方式 优先级
压缩包 zip、7z、rar、tar、gz、tgz 不解压到磁盘，逐个读取内部文件并提取 P1
单封邮件 eml、msg 解析主题、发件人、收件人、日期、正文；附件按其类型提取 P1
邮箱存档 mbox 逐封拆分后同单封邮件处理 P1
Outlook 数据文件 pst、ost 逐封拆分后同单封邮件处理 P2
  • 结果路径显示为「容器路径 › 内部路径」，例如 D:\归档\2024.zip › 合同\采购合同.docx，或 收件箱.mbox › 关于报销的通知 › 附件.xlsx。
  • 压缩包内的中文文件名自动识别 GBK 和 UTF-8 编码，避免乱码。
  • 嵌套层数默认最多 3 层（如邮件附件中的压缩包里的文档）。
  • 防压缩炸弹：单个压缩包解压总量默认上限 2 GB，单个内部文件压缩比超过 100 倍时跳过并记为失败。
  • 加密的压缩包跳过，标记「已加密」，内部文件名能读到时仍可按文件名搜索。
  • 打开容器内的文件时，先解出到软件的临时目录再用默认程序打开，并提示这是只读副本；临时文件在软件退出时清理。
  • 预览邮件时，在正文上方显示主题、发件人、收件人和日期。
  • pst 和 ost 体积大、解析库不够成熟，列为 P2，技术验证时一并评估。

5. 搜索功能

一个搜索框同时支持关键词、短语、布尔、正则、模糊和筛选条件；不熟悉语法时，可以用高级搜索面板以表单方式组合同样的条件。

查询语法：

写法 含义 示例
空格分隔 同时包含（AND） 合同 违约金
"..." 完整短语，按原顺序连续出现 "不可抗力条款"
OR 任一包含 报销 OR 差旅
- 或 NOT 不包含 张三 报销 -草稿
( ) 分组 (合同 OR 协议) 2025
NEAR/n 两个词相距不超过 n 个字，不限先后 甲方 NEAR/10 违约
~ 后缀 对该词做模糊匹配 合同审批~
/.../ 正则表达式 /1[3-9]\d{9}/
path: 路径包含（含压缩包和邮件的内部路径） path:D:\项目\2025
ext: / type: 扩展名 / 类别（文档、表格、演示、PDF、图片、文本、代码、压缩包、邮件） ext:xlsx、type:邮件
name: 只匹配文件名 name:周报
from: / to: 邮件发件人 / 收件人（名称或地址） from:张三
subject: 邮件主题 subject:报销
modified: 修改时间；邮件按发送日期 modified:2025-01..2025-06、modified:>30d
size: 文件大小 size:>10MB
vol: 所在卷（按卷标） vol:备份盘A

匹配规则：

  • 单个汉字、两个字的中文词都必须能精确搜到，不允许因分词方式而漏检。
  • 以下归一化始终生效：英文大小写、全角与半角、中文标点的全半角形式。繁简体归一默认开启，可在设置中关闭。
  • 搜索范围可选「内容和文件名」（默认）、「仅内容」、「仅文件名」。

模糊匹配（~ 或开关开启）：

  • 英文和数字按编辑距离容错：词长 5 至 8 允许 1 处差异，9 以上允许 2 处。
  • 中文按邻近匹配：查询词中的字按原顺序出现，相邻字之间最多夹 2 个字。例如 合同审批~ 可以命中「合同的审批」「合同签订审批」。
  • 模糊结果的相关度低于精确结果，排在其后。
  • 同义词扩展、拼音搜索为 P2。

正则表达式：

  • 语法采用 RE2 标准，不支持反向引用和环视；在帮助中写明这一点。
  • 默认不区分大小写，可切换；支持 (?s) 让 . 跨行匹配。
  • 执行方式：先从表达式中提取必然出现的字面文字，用索引筛出候选文件，再在候选文件的已提取文本上逐个匹配。
  • 提取不出字面文字时（如 /\d{18}/）对全部已提取文本扫描，显示进度，可随时取消，并可边扫边出结果。

其他：

  • 结果排序：相关度（默认）、修改时间、文件名、路径。
  • 普通关键词边输入边搜索（防抖 200 毫秒）；正则和全量扫描需按回车执行。（P1）
  • 搜索历史，以及可命名保存的常用搜索。（P1）
  • 高级搜索面板：用表单组合关键词、排除词、目录、类型、时间、大小，并实时显示等价的查询语句。（P1）

交互要求：

  • 常驻系统托盘，全局快捷键呼出搜索窗口（默认 Ctrl+Alt+F，可修改），按 Esc 隐藏。
  • 键盘可完成全部常用操作：上下键选择结果，Enter 打开文件，Ctrl+Enter 打开所在文件夹，Ctrl+C 复制路径。
  • 界面跟随系统浅色和深色主题。

7. 移动硬盘与网络映射盘

结论：移动硬盘拔掉后索引保留，照常可以搜索和预览提取出的文字，只是不能打开原文件；索引默认永久保留，由用户手动清理。移动硬盘上常放归档资料，拔掉后仍能知道「要找的东西在哪块盘上」，正是这类工具最有用的地方。

7.1 移动硬盘

编号 需求 优先级
F-VOL-01 按卷 ID（卷序列号 + 卷 GUID，辅以卷标和容量）识别磁盘，不依赖盘符；文件路径存为「卷 ID + 卷内相对路径」，显示时换成当前盘符 P0
F-VOL-02 盘符变化（如这次是 E:，下次是 F:）不影响索引，无需重建 P0
F-VOL-03 卷拔出后，索引保留，结果照常显示并标记「离线」，可预览提取文本 P0
F-VOL-04 打开离线文件时提示需接入哪块盘：卷标、上次的盘符、最后在线时间 P0
F-VOL-05 卷重新接入后自动识别，后台增量对账：比对路径、大小、修改时间，只处理新增、修改、删除的文件；对账期间可正常搜索，该卷结果标记「同步中」 P0
F-VOL-06 卷在线期间与本地盘一样实时监听文件变化 P0
F-VOL-07 不长期占用卷上的文件句柄，避免妨碍「安全弹出」；收到卷即将移除的系统通知时，立即释放句柄并暂停该卷的任务 P0
F-VOL-08 索引管理页列出每个卷的卷标、最后在线时间、文件数、索引占用空间，可手动删除某个卷的全部索引 P0
F-VOL-09 可选「超过 N 天未接入则自动删除该卷索引」，默认关闭 P2
F-VOL-10 接入一块从未索引过的移动硬盘时，发通知询问是否加入索引，默认不自动加入 P1
F-VOL-11 卷被重新格式化后视为新卷；遇到两块盘 ID 相同（如克隆盘）时，提示用户确认，不自动合并 P1

8. 索引维护与后台任务

后台任务按「先文件名、再内容、最后 OCR」的顺序推进，保证刚加入的目录很快就能按文件名搜到，耗时的 OCR 不拖慢其他工作。

处理顺序（优先级从高到低）：

  1. 文件变更（新增、修改、删除）
  2. 文件名和元数据入库
  3. 文本类和 Office 新格式、PDF 文字层的内容提取
  4. 老格式和 WPS 格式的转换提取
  5. OCR
编号 需求 优先级
F-BG-01 本地 NTFS 盘实时监听文件变化，增量更新索引 P0
F-BG-02 软件启动时对账，处理未运行期间发生的变化 P0
F-BG-03 文件移动或改名时，按内容哈希复用已有的提取结果和 OCR 结果，不重新处理 P1
F-BG-04 后台进程以低优先级运行；检测到用户正在操作电脑时降低处理速度 P0
F-BG-05 后台最多使用一半的 CPU 核心，可在设置中调整 P0
F-BG-06 笔记本使用电池时，默认暂停 OCR 和格式转换，接上电源后继续 P1
F-BG-07 可手动暂停、恢复全部任务或单个索引根的任务 P0
F-BG-08 程序退出、重启或崩溃后，从中断处继续，不从头开始 P0
F-BG-09 状态面板按索引根和卷显示：文件总数、已完成、待处理、OCR 队列长度、失败数、当前处理的文件 P0
F-BG-10 OCR 队列显示预计剩余时间，可暂停 P1
F-BG-11 失败列表显示文件和原因（已加密、已损坏、超时、无权限、不支持），可单个或批量重试，可直接加入排除规则 P0
F-BG-12 可重建单个索引根或全部索引；检测到索引数据损坏时提示重建 P0
F-BG-13 软件升级导致索引格式变化时，后台迁移，迁移期间旧索引继续可用 P1

9. 非功能需求

性能目标以 10 万个文件、固态硬盘、4 核 16 GB 内存的普通办公电脑为基准；标注「待校准」的数值在技术验证阶段用实测修正。

性能：

模糊搜索，首屏结果 P95 ≤ 1 秒
正则搜索（能提取出字面文字时） P95 ≤ 2 秒

可靠性：

  • 文件解析、格式转换、OCR 在独立子进程中运行；单个文件导致子进程崩溃或卡死时，自动重启子进程，跳过该文件并记为失败，主程序不受影响。
  • 索引写入采用事务，意外断电或强制结束进程后索引不损坏。
  • 本地日志按大小滚动保存，便于排查问题。

隐私与安全：

  • 索引中包含所有文件的文字内容，存放在 %LOCALAPPDATA% 下的软件数据目录，仅当前 Windows 用户可访问；数据目录位置可修改。
  • 软件不联网，不收集任何使用数据；检查更新功能默认关闭。
  • 删除某个索引根或卷的索引时，同时删除对应的提取文本和 OCR 缓存。
  • 索引数据库加密为 P2。

兼容性：

  • 支持 Windows 10 22H2 和 Windows 11，x64。
  • 支持超过 260 个字符的长路径，以及包含各种 Unicode 字符的文件名。

安装与部署：

  • 由三部分组成：主程序、格式转换组件（体积较大）、OCR 组件。
  • 提供包含全部组件的离线完整安装包，安装和使用全程不需要联网；同时提供便携版。
  • 卸载时询问是否保留索引数据。

10. 技术方案建议

建议以 Go 做主程序、TypeScript 做界面，耗时且不稳定的解析工作全部放进独立子进程；全文索引引擎、老格式转换和 OCR 三项在正式开发前先做技术验证再定。

变更来源把文件变化交给任务调度，调度按优先级把文件派发给子进程，拿回文本后写入索引库；搜索服务只读索引库，所以后台再忙也不影响搜索。

部分 建议 说明
主程序 Go 目录遍历和并发处理快，可打包成单个 exe
桌面框架 Wails v2 基于 WebView2；Windows 10 可能未预装运行时，离线安装包需附带
界面 TypeScript + React 结果列表用虚拟滚动
元数据与提取文本 SQLite（WAL 模式） 提取文本压缩存储，供预览、正则匹配和重建索引使用
全文索引 待验证：SQLite FTS5、Bleve、Tantivy 见下方验证项 1
Office 新格式 Go 解析 zip 内的 XML 无需外部依赖
PDF 文字层 优先 PDFium BSD 许可；MuPDF 为 AGPL、Poppler 为 GPL，若以后要对外分发需注意
老格式和 WPS LibreOffice 无头模式，常驻进程池 避免每个文件都启动一次 LibreOffice；备选 Apache Tika（需 Java）
OCR RapidOCR（PaddleOCR 模型的 ONNX 版本），CPU 推理 备选 Windows 自带 OCR 接口，需安装中文语言包
正则 Go 标准库 regexp 即 RE2 语法，与第 5 节一致
文件监听 ReadDirectoryChangesW NTFS 可选用 USN 日志加速启动对账
卷管理 卷序列号与卷 GUID 接口、设备移除通知 收到移除请求时释放句柄（F-VOL-07）

技术验证项（正式开发前完成）：

  1. 全文索引选型。 判断标准：一两个字的中文能否精确命中、短语和邻近查询、模糊匹配、10 万个文件下的查询延迟、增量更新速度、索引体积。注意 FTS5 的 trigram 分词器对少于 3 个字的查询无法使用索引，需要配合其他方案。
  2. 老格式转换。 用真实的 .doc、.xls、.ppt、.wps、.et、.dps 样本各约 100 份，测提取成功率和单个文件平均耗时。
  3. OCR。 用真实扫描件和图片测识别准确率和每页耗时，据此确定图片 OCR 的默认开关和预计耗时。
  4. 正则全量扫描。 测 10 万个文件提取文本的全量扫描时间，决定提取文本的压缩和分块方式。
  5. 首次索引吞吐。 测各类文件的每秒处理数，校准第 9 节中「待校准」的指标。
  6. 压缩包与邮件。 确认 7z、rar 的 Go 读取库能否不落盘逐个读取；用真实样本测 zip 中文文件名的编码识别、.msg 的解析成功率；评估 pst 解析方案是否可行。

11. 版本规划

分五个阶段推进，每个阶段结束时都是一个能用的版本；按卷 ID 存储路径（F-VOL-01）放在 M1 实现，避免以后迁移索引。

  1. M0 技术验证。 完成第 10 节的 6 项验证。完成标准：确定索引引擎、老格式转换和 OCR 方案，有实测数据支撑。
  2. M1 核心可用。 索引范围与排除规则；文本、Office 新格式、PDF 文字层；关键词、短语、布尔、筛选、文件名搜索；结果列表、预览、打开；托盘和全局快捷键；本地实时监听和启动对账；解析子进程隔离；按卷 ID 存储路径。完成标准：日常查找可以用它代替现有方式。
  3. M2 格式全覆盖。 老格式和 WPS 转换；扫描 PDF 和图片 OCR；压缩包和邮件；正则搜索；模糊匹配；失败列表与重试；后台资源控制。完成标准：第 4 节所有 P0 和 P1 格式可搜索。
  4. M3 移动硬盘与网络盘。 第 7 节全部 P0 需求：离线搜索、重新接入对账、安全弹出、网络盘定时扫描。完成标准：拔插移动硬盘、改变盘符后结果始终正确。
  5. M4 完善。 全部 P1 需求，如高级搜索面板、搜索历史、打开到命中位置、重复文件合并。

P2 需求在 M4 之后按实际使用情况决定是否做。

12. 不在本期范围与已确定事项

不在本期范围：

  • 多用户使用、局域网共享索引、服务器部署。
  • macOS 和 Linux。
  • 音频和视频转文字。
  • 云盘中仅在线、未下载到本地的文件内容。
  • 按语义查找（不含相同字词、但意思相近的内容）。

已确定事项：

  • 支持压缩包和邮件文件，见第 4 节。
  • 繁简体归一默认开启，可在设置中关闭。
  • 全局快捷键默认 Ctrl+Alt+F，可修改。
  • 界面采用 React。
  • 软件名称为「找找」（ZhaoZhao），见第 1 节。
